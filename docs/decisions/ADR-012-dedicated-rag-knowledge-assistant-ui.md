# ADR-012: Dedicated Hospital Knowledge Assistant Workspace & Evidence Provenance UI

## Context and Problem Statement

Following the completion of RAG Answer Generation (Chunk 4.4), HospitalOps AI established an evidence-grounded backend capable of synthesizing operational guidance with deterministic citation verification, clinical safety guardrails, and non-clinical boundary enforcement.

While an initial preview was integrated into Tab 4 of `KnowledgeBase.tsx`, hospital administrators and operations personnel required a dedicated, distraction-free workspace tailored for operational question answering, deep citation inspection, configuration tuning, and diagnostic observation.

Key challenges for the operational knowledge assistant interface:
1. **Security & XSS Prevention:** Answers generated by language models or retrieved from ingested hospital documents must be rendered safely. Using `dangerouslySetInnerHTML` or unconstrained markdown-to-HTML engines creates XSS risks if malicious text is ingested.
2. **Interactive Citation Linking:** References in answer text (e.g., `[S1]`, `[S2]`) must dynamically link to specific citation cards in the evidence panel with instant focus, smooth scrolling, and highlighting.
3. **Data Privacy & Ephemeral State:** Operational questions, sensitive facility policies, and generated answers must not leak into browser persistent storage (`localStorage` or `sessionStorage`), which could expose sensitive facility data on shared workstations.
4. **Subsystem Readiness & Observability:** The user must have real-time visibility into the health of the RAG generation pipeline, active model name, provider type, token accounting, and latency breakdown.
5. **Healthcare Safety Boundaries:** In accordance with `AGENTS.md`, every view must prominently display non-clinical operational advisories, preventing any confusion between operational decision intelligence and clinical medical authority.

---

## Decision Drivers

1. **Dedicated Cockpit UX:** Provide a dedicated top-level route `/knowledge/assistant` with direct sidebar navigation and launchpad links from the knowledge repository.
2. **Safe Markdown Rendering:** Parse markdown (headings, bold, lists, code, tables) into native React elements without raw HTML injection, embedding interactive `<CitationPill>` components directly into prose.
3. **In-Memory Tab-Local Session History:** Maintain session inquiry history strictly in React component state (in-memory). Zero queries or responses are written to `localStorage` or `sessionStorage`.
4. **Dual-Tier Evidence Inspector:** Separate evidence into "Cited in Answer" (directly referenced by `[S#]` tags) and "All Retrieved Candidates" (all chunks assembled within the token budget), providing complete transparency.
5. **Real-time Pipeline Health Diagnostics:** Integrate `GET /api/v1/knowledge/answer/health` into the assistant header to confirm embedding index readiness, active model, and chunk count.
6. **Backend Excerpt Provenance Support:** Enrich `CitationReference` contracts with `excerpt: str | None` so evidence cards can display exact matched passages without secondary lookups.

---

## Considered Options

1. **Retain Tab-Only Interface in `KnowledgeBase.tsx`:**
   - *Rejected:* Constrained width, crowded navigation alongside document upload and chunk exploration, poor support for complex multi-column diagnostic layouts.
2. **Third-Party Markdown Library with HTML Plugins (`react-markdown` + `rehype-raw`):**
   - *Rejected:* Introduces bundle bloat, increases supply-chain surface area, and risks XSS injection if untrusted documents contain raw HTML tags.
3. **Dedicated Modular Workspace (`/knowledge/assistant`) with Custom Safe Parser & In-Memory State:**
   - *Selected:* Implements componentized architecture under `components/knowledge/`, a lightweight XSS-free safe markdown renderer, bidirectional citation navigation, collapsible diagnostics, and in-memory session isolation.

---

## Decision Outcome

Adopted **Option 3**:

1. **Routing and Navigation (`App.tsx`, `Sidebar.tsx`):**
   - Registered dedicated routes `/knowledge/assistant` and `/knowledge-assistant`.
   - Added `Knowledge assistant` to the main navigation sidebar with a `Bot` icon.
   - Added launchpad card and link from Tab 4 of `/knowledge` to open the dedicated workspace.
   - Supported URL search query parameter `?q=...` for deep-linking queries from other views.

2. **Component Architecture (`frontend/src/components/knowledge/`):**
   - `AssistantHeader.tsx`: Live status badge from `GET /api/v1/knowledge/answer/health`, back breadcrumb, non-clinical disclaimer, and session history drawer toggle.
   - `QuestionComposer.tsx`: Multi-line auto-expanding textarea, 500-character counter, keyboard shortcuts (Enter to submit, Shift+Enter for newline), clear button, and input preservation upon errors.
   - `SuggestedQuestions.tsx`: Categorized operational question pills (Bed Allocation, Surge Protocols, Equipment Maintenance, Regulatory Compliance).
   - `AdvancedSearchSettings.tsx`: Collapsible accordion controlling Top-K, Token Budget (500–8,000), Max Sources, Category Scope, Access Level Scope, Temperature, and Require Citations with "Reset to Defaults".
   - `SafeMarkdownAnswer.tsx`: XSS-safe parser converting markdown blocks into native React elements while replacing `[S\d+]` with interactive `CitationPill` components.
   - `CitationPill.tsx`: Accessible interactive badge with hover tooltip showing source title, category, and similarity score; triggers smooth scroll and selection in evidence panel.
   - `AnswerStatusBadge.tsx`: Visual badge reflecting `AnswerStatus` and `AnswerType` (Grounding level, Confidence score).
   - `CitationEvidencePanel.tsx`: Dual-tab evidence viewer ("Cited in Answer" vs "All Retrieved Candidates"), filterable by selected citation pill (`[S1] ✕`), with expand/collapse passage excerpts.
   - `GenerationMetadataPanel.tsx`: Collapsible diagnostics drawer displaying model name, provider, latency breakdown (retrieval vs generation), token usage, and citation validation metrics.
   - `SessionHistoryDrawer.tsx`: In-memory slide-over drawer displaying past queries and answers in the current browser tab, enabling 1-click query restoration.
   - `AssistantEmptyState.tsx`, `AssistantLoadingState.tsx`, `AssistantErrorState.tsx`: Specialized state views for empty, loading, and error states.

3. **Backend Contract Alignment (`contracts.py`, `citation_validator.py`):**
   - Added `excerpt: str | None = Field(default=None)` to `CitationReference`.
   - `CitationValidator` automatically populates the excerpt string from retrieved context blocks during both verified citation creation and candidate citation compilation.

---

## Consequences

### Positive
- **Streamlined Decision-Making:** Administrators can query hospital SOPs, protocols, and capacity guidelines with complete citation provenance in a purpose-built workspace.
- **XSS Immunity:** Direct conversion from text tokens to React nodes guarantees zero execution of malicious scripts from unverified documents.
- **Zero Privacy Leakage:** Hospital operational queries and generated summaries remain strictly in volatile memory for the active session, avoiding persistent local disk footprints.
- **Explainable Evidence:** Users can trace every operational recommendation directly to the exact document, section, and text excerpt from which it was derived.

### Compliance & Governance
- All views strictly reinforce the non-clinical boundary with conspicuous advisory banners: *"Advisory Only — HospitalOps AI provides operational guidance only. Do not use for clinical diagnosis or patient medical management."*
- Full telemetry transparency: Latencies, token usage, model identifiers, and validation status are explicitly exposed to users for complete auditability.
